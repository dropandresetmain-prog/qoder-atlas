## Behavioural semantics

- Supplier service/reservation truth is stored separately from Journey intent.
- One shared reservation owns its lines once; allocations explicitly name each
  Traveller and optional JourneyItem. A named JourneyItem must belong to the
  same Traveller. Cross-Trip allocations are supported.
- Reservation confirmation and line confirmation do not create an entitlement.
  Ticket/coupon/voucher issuance has its own observed status, time, and issuer
  evidence; protected identifiers use the `ProtectedDataRef` triple.
- Published, estimated, and actual service times retain separate observed
  values and provenance. Stale observations do not overwrite newer facts.
- External records preserve provider identity/order metadata. Unknown and
  ambiguous identity states are quarantined; only a separate evidence-backed
  link can produce `LINKED`. Link retirement cannot strand a false `LINKED`
  state.
- Observation, servicing capability, and authority are separate. Missing
  capability and explicit `supported=false` both produce a typed unavailable
  result; no authority is granted by a capability row.
- Offers are immutable, expire at the boundary, and are eligible only through
  explicit Traveller/Organisation/agreement-scope facts. Agreement-scope
  publication/effective/validity windows are checked by the read query.
- Amounts and FX rates remain exact decimal values. FX observations are
  immutable, dated, sourced, and pair-checked for organisation-payer cost
  allocations. Actual costs require evidence.
- Commands validate target UUIDs before entering the UnitOfWork, use accepted
  JSON receipt replay semantics, precompute IDs/timestamps outside retryable
  callbacks, and contain no provider/model side effects.

## Repository, command, and query seams

`PgArrangementRepositories` exposes typed repositories for services, resources,
reservations, entitlements, offers/agreements, external integration, and
accounting. It is workspace-scoped and uses the ambient transaction client;
there is no generic save path.

`arrangementCommands.ts` provides deterministic command boundaries for creation,
observations, allocation, entitlement linkage, offers/agreement scopes,
external identity/capability facts, ownership bindings, budgets, costs, and FX.
Database errors are mapped to typed conflicts. `PgArrangementReadQueries`
provides reverse lookups for allocations, lines/services, Traveller
reservations, entitlements, eligible offers, external/quarantined records,
capabilities, reservation costs, and fresh FX pairs.

## M6 reverse lookups

The query seams and indexes are sufficient for M6 to trace:

- service -> reservation lines -> allocations -> JourneyItems/Journeys/Trips;
- reservation -> all affected Travellers and line-level supplier states;
- line -> entitlements and people;
- offer -> explicit eligibility and valid agreement scope;
- canonical subject -> live external identity links;
- connection -> quarantined records and capability facts;
- reservation -> intended/actual cost allocations and cited FX evidence.

M6 evaluation, invalidation, geography, and assessment persistence were not
implemented in this milestone.
