- source capture and protected content-reference triples;
- evidence records with source and typed-subject provenance;
- independent publisher information lineages and immutable information
  editions, including advisory, condition and regulatory detail tables;
- exact regulatory publication references to a published RuleSetVersion;
- immutable rule-set editions with a bounded recursive grammar and explicit
  publication/effective lifecycle;
- typed rule assignments by organisation, subject, jurisdiction or registered
  population predicate;
- immutable explicit/inferred preferences, objectives, typed constraint
  definitions and scalar/subject operands;
- typed information scopes and named reverse lookups for M6;
- explicit coverage states `COMPLETE`, `INCOMPLETE`, `UNKNOWN`,
  `UNSUPPORTED_CATEGORY` and `SOURCE_UNAVAILABLE`, with expiry;
- structured information quarantine for duplicate hash conflicts and
  out-of-order editions.

No global source precedence is stored. No information table contains an entry
decision. A constraint definition contains no evaluation result.

## 3. Important integration decisions

- M2 evidence FKs were closed additively in `0085_m2_evidence_fk_closure.sql`;
  M2 fixture evidence pools were updated instead of weakening those FKs.
- M4 geography columns remain typed UUIDs with indexes and documented deferred
  FKs; M5 does not create geography tables.
- The command callbacks precompute generated UUIDs and use the ambient
  transaction client, so serializable retries do not mint different rows.
- Equal sequence and equal payload hash is a durable duplicate replay; equal
  sequence with a different hash is quarantined. A lower-than-latest unseen
  sequence is quarantined as `OUT_OF_ORDER`.
- M6 receives typed ports for applicable information, assignments, scopes,
  expiry, coverage, governing objectives and governing constraints. It must
  perform deterministic viability/evaluation; M5 does not.
