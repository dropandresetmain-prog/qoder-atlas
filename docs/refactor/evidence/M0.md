## Base SHA discrepancy (self-corrected)

The dispatch brief's "verified starting SHA" was
`8eefd220e031c0abed306305a1628b5e033cc0ef`. At package start, the local
clone's `data-structure-refactor` was at `29118bccacbca02b48334030e335eb94d2858d52`
and had never fetched `8eefd22...`, so a local `git log`/`git rev-parse`
could not resolve it. I initially (incorrectly) concluded the SHA was
malformed — a miscount, not a real defect — and proceeded from `29118bc`
without fetching first. `git fetch origin data-structure-refactor` later
confirmed `8eefd22...` is a real, valid, 40-character commit
("docs: index Northstar models arsenal") seven commits ahead of `29118bc` on
the actual remote branch. Before pushing, I diffed `29118bc..8eefd22` and
confirmed the intervening commits touch only `AGENTS.md`, `README.md`,
`docs/ARCHITECTURE.md`, `docs/CAPABILITIES_AND_LIMITATIONS.md`,
`docs/ROADMAP.md`, `docs/BUILD_WITH_QODER.md`, `docs/README.md`, and add
`docs/AGENT_MODEL_SELECTION.md`, `docs/IMPLEMENTATION_AGENT_ROUTING.md`,
`docs/MODELS_ARSENAL.md` — model-routing and orchestration documentation
only. None of `docs/IMPLEMENTATION_PLAN.md`,
`docs/DATA_STRUCTURE_ARCHITECTURE_CLOSURE.md`,
`docs/DATA_STRUCTURE_LOGICAL_SCHEMA.md`, `docs/TESTING.md`, `src/**`,
`test/**`, `fixtures/**` or `package.json` changed, so this M0 package's
contracts and fixtures are unaffected by the missed fetch. I rebased the M0
commit onto the actual `8eefd22` tip (clean, no conflicts) and re-ran
typecheck/lint/build/anti-hardcoding-gate/full-suite on the rebased tree
before pushing. **Process lesson, not an architecture gap**: fetch the
remote branch before trusting a local HEAD as the dispatch base, even when
the local working tree is clean.

## Migration/legacy inventory

Full inventory and per-table mapping: [`../MIGRATION_MAPPING.md`](../MIGRATION_MAPPING.md).
Produced by a bounded read-only research pass over `src/persistence/**`,
`src/app/{dossierStore,fxStore,eventInboxStore,preferenceStore}.ts`,
`src/domain/**`, `src/operational/**` and `fixtures/**`. Key flags carried
forward as **Act Now / Investigate before migration rehearsal** (M10):

1. Multi-traveller `Trip.elements[]` has no recorded per-Journey ownership —
   allocation must be justified per element, never guessed.
2. Traveller identity is split across three disconnected tables
   (`entities.TRAVELLER`, `booking_dossiers`, `preferences`) with no FK
   enforcing one canonical person.
3. `AnchorEvent` conflates Event+Programme+ProgrammeItems in one nested
   object; the Event/Programme split point needs an explicit migration rule.
4. `RecoveryCase`'s single case-wide approval envelope needs a projection
   rule into the target's per-intent `approvals` model.
5. `Constraint.status` is currently stored on the definition, which the
   target schema explicitly forbids (status belongs to `assessments`).
