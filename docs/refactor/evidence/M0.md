## Migration/legacy inventory

Full inventory and per-table mapping: [`../MIGRATION_MAPPING.md`](../MIGRATION_MAPPING.md).
Produced by a bounded read-only research pass over `src/persistence/**`,
`src/app/{dossierStore,fxStore,eventInboxStore,preferenceStore}.ts`,
`src/domain/**`, `src/operational/**` and `fixtures/**`. Key flags carried
forward as **Act Now / Investigate before migration rehearsal** (M10):

1. Multi-traveller `Trip.elements[]` has no recorded per-Journey ownership —
   allocation must be justified per element, never guessed.
2. Traveller identity is split across three disconnected tables
   (`entities.TRAVELLER`, `booking_dossiers`, `preferences`) with no FK
   enforcing one canonical person.
3. `AnchorEvent` conflates Event+Programme+ProgrammeItems in one nested
   object; the Event/Programme split point needs an explicit migration rule.
4. `RecoveryCase`'s single case-wide approval envelope needs a projection
   rule into the target's per-intent `approvals` model.
5. `Constraint.status` is currently stored on the definition, which the
   target schema explicitly forbids (status belongs to `assessments`).
