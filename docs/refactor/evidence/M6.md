## 2. WorldSnapshot and read consistency (closes G1)

Decision (M2_INTEGRATION_DECISIONS.md G1: M6 owns it, UnitOfWork unchanged):

- `ReadSessionFactory` / `ReadSession` (`src/resolution/world/readSession.ts`)
  is a **separate** abstraction from the mutation `UnitOfWork`. The PostgreSQL
  implementation (`src/persistence/postgres/world/pgReadSession.ts`) opens one
  pooled connection with `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`.
  Every query in the session sees the snapshot fixed by its first statement;
  PostgreSQL refuses writes (`read-only transaction`). No idempotency claim,
  head locks, SERIALIZABLE retry loop or receipt — reads are not commands.
- The session records its `pg_current_snapshot()` and transaction timestamp
  as the capture identity, and owns a manifest recorder so a reader cannot
  capture rows without the manifest entries that make them checkable later.
- `PgWorldReader.capture` (`pgWorldReader.ts`) runs discovery, loading and
  manifest recording inside that session; evaluation runs **after** the
  session ends, over the immutable `CapturedWorld` (logical schema §11.2).
- Evaluators are pure functions of `(subject, { now, world, effective })`; no
  evaluator imports a repository or persistence module.

Proof (`postgres-integration/m6WorldSnapshot.pgtest.ts`): a head advance
committed by an independent connection while the session is open is invisible
inside it; a write through the session is rejected; the post-session read sees
the committed value.

## 4. Scope-generation propagation (`0090`)

Finding at integration (I-5, Act Now): only two M2 commands advanced any scope;
M3/M4/M5 advanced none, so an inserted participation, allocation, rule
assignment or publication could not invalidate anything.

`0090_scope_generation_propagation.sql` attaches row triggers to 52 owning
tables that advance the affected scopes **inside the writing transaction** —
a handler, seed or import cannot skip them and a rollback removes the advance.
Unmapped tables fail loudly. Rules:

- at most one advance per scope per transaction (`last_advanced_xact`), shared
  with `PgScopeGenerationLedger.advance`, so triggers and explicit command
  advances compose instead of double counting (M2's "Trip scope advances
  exactly once per membership change" assertion still holds);
- TRIP scope = membership only (Journey insert/delete/moved/lifecycle), Trip
  row edits are caught by the Trip head; the Trip creation itself advances
  nothing (no snapshot can have read a Trip before it existed);
- information on a topic not in `registered_information_topics` also advances
  `INFORMATION_TOPIC:m6:unregistered-topic`, which every snapshot reads —
  unclassified information cannot evade invalidation (closure §6);
- a population-predicate rule assignment advances
  `ORGANISATION_RULES:m6:population-predicate` (conservative, closure §6).

The sentinel scope ids were renamed from `*…*` forms to
`m6:unregistered-topic` / `m6:population-predicate` after Checkpoint B because
the frozen `ScopeGenerationRef.scopeId` pattern rejects `*`; `0090` had only
been applied to throwaway test databases and is unmerged.

## 5. Dependency registry and causal structure

`src/resolution/impact/closure.ts` `DEPENDENCY_REGISTRY` — the closed set of
executable semantics (`DependencySemanticSchema`), each with from/to kinds and
propagation direction (FROM_TO or BOTH). FKs are read to find edges; an edge
exists only when a registered semantic names it. Highlights:

- supplier: `SERVICE_SUPPLIES_LINE`, `LINE_OF_RESERVATION`,
  `ALLOCATION_FULFILS_ITEM`, `LINE_ALLOCATED_TO_TRAVELLER` (only when the
  allocation names no item), `SERVICE_SELECTED_FOR_ITEM`,
  `ENTITLEMENT_COVERS_LINE`, `ITEM_OF_JOURNEY`;
- programme: `PROGRAMME_ITEM_OF_PROGRAMME`, `PARTICIPATION_IN_PROGRAMME_ITEM`,
  `PARTICIPATION_OF_TRAVELLER`, `ENGAGEMENT_REFLECTS_PARTICIPATION`,
  `RESOURCE_ASSIGNED_TO_ACTIVITY` (BOTH), `RESOURCE_USED_BY_LINE` (BOTH);
- geography/knowledge: `PLACE_LOCATES_ACTIVITY`, `JURISDICTION_CONTAINS_PLACE`
  (membership or PostGIS containment), `VISIT_TO_JURISDICTION`,
  `INFORMATION_SCOPED_TO_{JURISDICTION,AREA,SUBJECT}`,
  `RULE_ASSIGNED_TO_{SUBJECT,ORGANISATION,JURISDICTION}`,
  `PUBLICATION_OF_RULE_SET_VERSION`;
- coordination/support: `GROUP_MEMBERSHIP` (BOTH), `SUPPORT_REQUIRED_BY_TRAVELLER`,
  `SUPPORT_PROVIDED_BY_TRAVELLER`, `JOURNEY_OF_TRAVELLER`, `JOURNEY_IN_TRIP`
  (Trip → Journey only: one Journey changing never fans out to co-travellers),
  `ORGANISATION_RESPONSIBLE_FOR`, `OBJECTIVE_OF_OWNER`, `CONSTRAINT_OF_OWNER`;
- explicit rows: `EXPLICIT_CONNECTS_TO` (upstream→downstream) and
  `EXPLICIT_REQUIRES` (emitted prerequisite→dependent).

Closure is a pure breadth-first walk with a visited set: cycles terminate, the
result is independent of edge order, unregistered or kind-mismatched edges are
reported and never traversed, and depth truncation is explicit. No graph
database; PostgreSQL remains authoritative.

Causal structure (`src/contracts/v2/assessment/explanation.ts`): every
dimension carries `CausalExplanation[]` with cause, affected subject, typed
dependency path, related subjects, evidence refs, assessment dimension,
resulting status, registered reason code, typed facts and uncertainty.
`reasons: string[]` remains for display only. `buildBlastRadius`
(`src/resolution/impact/blastRadius.ts`) exposes causes, affected subjects with
paths, and per affected Journey the blocking issues, failed requirements and
uncertainty — no prose parsing.

## 6. Effective projection ownership

`src/resolution/world/effectiveItinerary.ts` derives a view, never a copy:

| Value | Owner | Basis in projection |
|---|---|---|
| Transport times | TransportService field groups | `ACTUAL` > `ESTIMATED` > `PUBLISHED` (published never overwritten); intent window only when no service (`INTENDED`), else `UNKNOWN` |
| Engagement times/place | ProgrammeItem (canonical schedule) | `PROGRAMME_SCHEDULE`; standalone appointment otherwise |
| Stay/resource interval | Reservation line (supplier) | `SUPPLIER_INTERVAL`, else intent |
| Booking state | Reservation + line (+ entitlements) | `bookingValid` VALID/INVALID/UNKNOWN, independent of Journey viability |
| Intent | Journey / JourneyItem | desired places, flexibility, lifecycle |

Divergences (booked service ≠ selected service, service endpoints ≠ intent,
booked place ≠ intended place) are surfaced as codes, never silently resolved.
"BOOKING VALID, JOURNEY INVALID" is representable by construction.

## 7. Invalidation, currentness and reassessment (`0091`)

- `assessments`, `assessment_subjects`, `assessment_results` (typed explanation
  JSON, bounded, schema-versioned), `assessment_inputs` (AGGREGATE / SCOPE /
  EVIDENCE / EVALUATOR rows with reverse index) — all immutable; supersession is
  an explicit single-successor chain. `ASSESSMENT` subtype activated by M6.
- Durable work: triggers on `aggregate_heads` updates and `scope_generations`
  inserts/updates enqueue `scheduled_reassessments` for the latest assessments
  whose recorded input differs, in the same transaction as the change; one open
  unit per subject+kind (coalesced). Clock expiry: `enqueueDueReassessments(now)`
  over `next_invalidation_at` (downtime catch-up).
- `currentAssessmentView` recomputes currentness from current heads/generations
  and the injected clock: CURRENT / STALE / PENDING_REASSESSMENT / UNAVAILABLE /
  NONE with typed staleness reasons. A UI cache is never consulted.
- `PgReassessmentWorker`: lease + fencing token claims (`FOR UPDATE SKIP
  LOCKED`), injected pipeline (capture → project → evaluate), result stored and
  claim completed atomically with supersession; failure → PENDING with backoff,
  then UNAVAILABLE after bounded attempts; a fenced worker cannot complete; a
  change committed during the pipeline leaves new work behind.

Adding a category (AT21): write a pure `Evaluator` over captured rows, declare
its dimensions and information topics, and add it to the registry.

declared topics become snapshot scope reads automatically; information on a
topic nobody registered still invalidates through `m6:unregistered-topic`.
A new row type additionally needs a typed M5 table/command and a reader in
`pgWorldReader` (M5/M9 portions of AT21), never a generic JSON bucket.

## 10. Blast-radius / explanation API

`evaluateImpact(pool, { workspaceId, focus, now, registry, persist? })` returns
`{ world, effective, assessments, blastRadius }`. `BlastRadiusView` carries
`causes`, `affectedSubjects[{subject, cause, depth, path}]` and per affected
Journey `traveller`, `trip`, `path`, `overallVerdict`, `blockingIssues`
(typed explanations), `holding`, `failedRequirements` and `uncertainty`.
`m6Acceptance` asserts every reason code is registered snake_case, every path
edge is a registered semantic and every fact is a typed scalar — M9 needs no
prose parsing.
