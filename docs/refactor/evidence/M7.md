## 2. RecoveryStrategy model

Immutable/versioned candidate (`src/contracts/v2/scenario/recoveryStrategy.ts`):

- `strategyVersion`, `status` (PROPOSED/EVALUATED/SELECTED/REJECTED/SUPERSEDED)
- `baseManifest` + `basisAssessmentId`
- `affectedSubjectRefs`, typed `scenarioChange`
- `assumptions` / `requiredUnknowns`
- per-subject `candidateAssessments` + optional full results
- `viability`: VIABLE / NOT_VIABLE / NOT_EXECUTABLE / STALE_BASE / REJECTED
- `requiredAuthorityScopes` (represented for M8; never granted here)

`strategyViabilityFromSubjectVerdicts`: any FAIL → NOT_VIABLE; any UNKNOWN or
required unknowns → NOT_EXECUTABLE (not executable); all PASS → VIABLE.

## 3. ScenarioChange / overlay

Closed `ScenarioEffect` union (M0) plus additive I-7 `disposition` on
`WAIVE_OBJECTIVE` (`WAIVED` \| `CLOSED_WITH_LOSS`).

Overlay (`src/resolution/scenarios/overlay.ts`):

- deep-clones `CapturedWorld`; never aliases or mutates the caller's base
- projects SELECT_OFFER / PROPOSE_ALLOCATION / CHANGE_PROGRAMME_ITEM_TIME /
  ALTER_JOURNEY_ITEM_INTENT / CHANGE_SUPPORT_ASSIGNMENT / WAIVE_OBJECTIVE
- rejects unresolved offers (no fabrication)
- rejects mutation of constraints, rule editions, transport observations,
  reservation observation status, and credential editions
- records `requiredAuthorityScopes` for M8

## 4. M6 candidate-evaluation seam

`evaluateRecoveryStrategy` (`src/resolution/scenarios/evaluate.ts`):

- applies overlay → `projectEffectiveWorld` → `assessSubject` with
  `createM6Registry()` (same registry as current-world evaluation)
- assesses every affected Journey reached through registered dependency
  semantics / programme participation / explicit affected refs
- proves canonical world JSON unchanged after evaluation

No second planner viability engine.

## 6. ActionPlan / ActionIntent

Compiler (`src/resolution/planning/compiler.ts`):

- maps each ScenarioEffect to a typed ActionIntent (no upsert escape hatch)
- capability check: internal namespaces allowed structurally; external
  `external:offer.select` requires explicit `supported: true`
- fingerprints, expected observations, authority scopes, preconditions filled
  for M8
- refuses STALE_BASE / NOT_EXECUTABLE / non-VIABLE strategies

## 7. DAG semantics

Default ordering: SELECT_OFFER → PROPOSE_ALLOCATION → CHANGE_PROGRAMME_ITEM_TIME
→ WAIVE_OBJECTIVE. `validateActionPlanAcyclic` rejects cycles; compiler never
emits cycles; tests force a cycle and assert rejection.

## 8. ProgrammeItem recovery

`CHANGE_PROGRAMME_ITEM_TIME` is first-class. Overlay updates programme schedule
(INTERNAL/SHARED authority only), expands affected travellers/journeys, and
evaluates each Journey separately through M6 (one may improve, another worsen;
overall VIABLE only when no mandatory FAIL remains).

## 9. Shared-object / multi-person

Affected subjects include shared reservation allocations and programme
participants. Whole-strategy viability aggregates every assessed Journey —
fixing one Journey while failing another mandatory scope is NOT_VIABLE.

## 10. Stale-base handling

When `currentState` is supplied, `assessManifestCurrentness` runs before
evaluate/compile. Stale base → strategy `viability: STALE_BASE` and compile
conflict `STALE_AGGREGATE_REVISION`.

## 11. AI / deterministic boundary

AI may propose typed ScenarioChanges only. Deterministic path:

`schema validate → overlay → M6 assess → viability → ActionPlan compile`

No AI → provider/money-moving API. No supplier confirmation fabrication. No
rule/constraint/credential edits. No M8 authority grant. No M9 UI.
